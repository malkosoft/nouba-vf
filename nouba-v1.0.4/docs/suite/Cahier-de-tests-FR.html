1. Objet & portée

Ce cahier décrit les scénarios de test de Nouba Pro, la matrice de couverture par module, et sert de procédure de non-régression à rejouer avant chaque livraison. Objectif : garantir un logiciel fiable, stable et sans régression.

Portée : borne, écran d'affichage, annonces vocales (TTS), suivi mobile par QR, administration, poste agent, licence, impression, thèmes, et intégrité de la base de données.

4. Procédure de non-régression (à rejouer avant livraison)

  1. Build : dotnet build -c Release → 0 erreur, 0 avertissement.
  2. Démarrage : lancer l'exe, ouvrir /health → 200.
  3. Borne / Affichage : prendre un ticket, l'appeler → affichage + une seule annonce dans la bonne langue.
  4. Multilingue : basculer FR → AR → EN → TZ sur la borne, vérifier textes et noms de service.
  5. Suivi QR : scanner le QR (Wi-Fi puis 4G), activer les alertes, vérifier les 3 paliers.
  6. Admin : se connecter ; tester la suppression d'un service/guichet/agent affecté → message clair, jamais de 500.
  7. Thèmes : basculer clair / sombre / auto / contraste dans l'admin et l'agent.
  8. Licence : sur base neuve, vérifier l'essai 7 jours.

5. Résultat global

Statut : CONFORME
L'ensemble des scénarios ci-dessus est réussi. Aucune régression détectée sur les fonctions existantes (borne, affichage, TTS, multilingue, licence, impression) après l'ajout des thèmes, la refonte de l'admin client, la clarification des langues, la robustesse des suppressions et les alertes de suivi à 3 paliers.
